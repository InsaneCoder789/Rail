# Rail V2 Security Review

Review updated: 12 October 2026. Baseline: `80e09e4`. Active development branch: `main`.

This is a source review and regression record, not a penetration-test certification. Runtime source, API entrypoint, persistence schema, workflow and tests were examined. Root documents and deliverables were inventoried; selected architecture documents were checked for drift. Archived ZIPs and rendered diagrams have not received a fresh visual review. No production deployment or provider sandbox was tested.

Severity measures potential impact. A finding does not imply every issue is reachable without authentication.

## Findings

| ID | Severity | Evidence and failure scenario | Status and next action |
|---|---|---|---|
| SEC-01 | Critical | `server/routes/authRoutes.ts` ignored wallet insertion conflicts, then attached a new user to that existing wallet. Knowing an unregistered wallet identifier could grant access. | Fixed: conflict and transaction rollback. Live PostgreSQL test verifies ownership and funds are unchanged. |
| SEC-02 | High | `persistence/postgresRateLimiter.ts`: row locking cannot lock an absent bucket; parallel first calls could overwrite the hit counter. | Fixed: create before locking. Twelve concurrent requests at quota three admit exactly three. |
| SEC-03 | High | Login/register quotas included caller-selected usernames. Rotating usernames created new quotas. | Fixed IP-level bypass and account-level address rotation: login applies both IP and hashed-account quotas through the shared limiter. Successful attempts count too. The temporary quota is not adaptive lockout; shared NAT clients and targeted accounts can experience throttling. |
| SEC-04 | Medium | Auth and execute routes cast JSON without object checks; null could trigger 500. | Fixed at authentication/execute boundaries; auth tests cover null, arrays, strings and numbers. |
| SEC-05 | Medium | Registration allowed inputs beyond bcrypt's 72-byte limit. Password suffixes could be ignored. | Fixed: eight-character minimum and 72 UTF-8 byte maximum. Existing longer passwords need an explicit reset plan. |
| SEC-06 | High | Financial commit, replay result and expiry ordering previously diverged. | Fixed for the durable payment path: mutations, transaction fingerprint, execution record, events and replay result commit together. Backend-termination and expired-authorization HTTP replay tests pass. Unverifiable historical crash records require operator reconciliation rather than guessed recovery. |
| SEC-07 | High | Shared outbox, event durability and external delivery. | Payment events use isolated buffers and insertion before financial commit. Durable delivery now has leases, attempts, acknowledgement, exponential retry and dead letters; concurrency, crash recovery and timeout tests pass. Operators must schedule the HTTPS worker and receivers must deduplicate stable event IDs. Non-payment event error handling and SSE lifecycle remain under SEC-18. |
| SEC-08 | High | Fingerprints omitted authorization IDs and signing encodings were ambiguous. | Fixed: versioned JSON arrays and authorization-bound fingerprints; delimiter-collision tests pass. Verified legacy completed records migrate without rerunning money. Missing/ambiguous historical fingerprints fail closed; old client HMACs must be regenerated. |
| SEC-09 | High | Complete binding was formerly left to HTTP. | Fixed for execution and recovery: claims match all financial fields; recovery requires matching transaction fingerprint, used authorization and balanced ledger. Usage conflicts abort the transaction. |
| SEC-10 | High | Nested client acquisition and session advisory locks. | Fixed: single transaction/client per payment and transaction-scoped locks; lock/statement deadlines and failed-client disposal are tested. One-connection-pool concurrent replay and real backend termination pass. Provider-specific pooler deployment remains unverified. |
| SEC-11 | High | Direct offline-token calls accepted invalid amounts; rollback could restore capacity without a matching reservation or restore it repeatedly. | Fixed for new reservations: both stores validate safe positive caps/spends and bounded issuance lifetimes. Transaction-keyed, payload-bound spend records make reservation, finalization and rollback idempotent; finalized spends cannot be refunded by rollback. PostgreSQL records share the payment transaction and lock spend identity plus token. Regression tests cover both backends. Historical unrecorded reservations require reconciliation, not an invented refund; retention cleanup remains a separate operational task. |
| SEC-12 | High | Implicit serverless proxy trust and unchecked service key length. | Fixed: proxy trust requires explicit configuration and production service keys require at least 32 non-whitespace characters. Config tests pass. Provider sanitation and operational key rotation still require deployment verification. |
| SEC-13 | High | Concurrent initial issuance and serverless expiry cleanup. | Code fixes delivered: issuance uses a transaction-scoped lock; authorization reads and issuance release expired reservations transactionally, with row locks and guarded wallet updates. Concurrent reads/sweeps cannot double-refund; inconsistent reservations abort without marking the authorization expired. Pools are explicit dependencies, not mutable global state. `npm run authorizations:sweep` supplies a bounded one-shot cleanup job for unattended records. Production scheduling/monitoring must still be configured and verified by the operator. |
| SEC-14 | Medium | Authentication errors, algorithm policy and credential lifecycle. | Invalid/expired JWTs return 401; HS256, bounded lifetime and credential-version claims are enforced. Logout-all advances the database version and invalidates prior tokens on subsequent requests across instances. Old versionless tokens require fresh login. Adaptive delay and public recovery flows remain outside the implemented bounded quota; manual resets must increment the version. |
| SEC-15 | High | Risk depended on caller-selected transaction IDs; challenge events did not stop execution. | Placeholder removed. No enforced fraud policy is claimed. Optional trained ML emits shadow observations only. Rules/step-up and real-data validation remain open. |
| SEC-16 | High | Conflicting wallet conventions; insufficient reconciliation and commit-level accounting invariants. | Wallet stores consolidated; deferred guards enforce complete payment records plus opening-balance and reservation equations. Wallet identity/baselines and posted history reject mutation. Snapshot-consistent reconciliation detects historical drift, currency and record mismatches; bounded reports cannot silently claim completeness. The maintenance job exits nonzero on findings. Historical baselines are never inferred and require reviewed evidence; unresolved wallet findings block recording. The existing development dataset has unresolved findings and is not an acceptance dataset. Controlled funding/reversals/refunds and least-privilege production roles remain open; owners can bypass guards and must not be runtime credentials. |
| SEC-17 | Medium | Semaphore handoff, retry cancellation and an unused stage timeout race. | Semaphore/retry fixes remain tested. Removed the unused timeout wrapper that could report failure while work continued, rather than attaching it to financial commit. Durable execution uses SQL deadlines and stored replay state. An uncertain commit response must be retried with the same payload/key, not interpreted as proof of cancellation. |
| SEC-18 | Medium | Event reads filtered a bounded global list; SSE could publish failed writes or lose payment notifications. | Fixed bounded SQL wallet filtering, stable-ID history pagination, committed database polling, handled stream errors, credential rechecks, backpressure cleanup and connection/lifetime caps. Nine regressions cover isolation, pagination and lifecycle. SSE is explicitly advisory, not a durable replay subscription; REST recovery and deployment-wide resource limits remain required. |
| SEC-19 | Medium | Oversized bodies destroyed the socket before reliably returning 413; missing deadlines and unbounded memory stores allowed resource growth. | Fixed absolute body deadlines, interrupted-read cleanup and JSON 413/408 flush-before-close behavior. Memory DLQ/quota/replay stores have caps; completed replay records are never evicted to admit new work. Synchronous replay failures retry correctly and returned state is defensive. Eight regressions pass, including real sockets. Financial database retention and provider transport limits remain operational work. |
| SEC-20 | Medium | The HSM placeholder advertised unimplemented providers; server HMAC cannot safely be shipped to devices. | Removed the placeholder module/export; startup rejects unsupported KMS/PKCS#11 settings. Server HMAC remains server-only. Device signing/enrollment/revocation and a real KMS adapter remain real-money expansion gates; offline authorization still requires preissued server records. |
| SEC-21 | Low | README recommended URL credentials and adding an already present license; deployment text described PostgreSQL rate limits as process-local. | Corrected in V2 documentation; archived local manuals remain older snapshots. |
| SEC-22 | High | Migration constraint checks matched names across every schema; legacy API-key detection also scanned foreign schemas. Constraint installation could be silently skipped or a legacy path entered for the wrong table. Parallel DDL was not serialized. | Fixed: constraint checks bind to the actual relation, legacy checks use the current schema, and runtime/outbox migrations take one transaction-scoped advisory lock with deadlines. Tests exercise six concurrent migrations, foreign legacy tables, local check/FK enforcement and rollback of partial schema changes. Historical data that violates a required check still needs explicit reconciliation; migration does not alter balances to hide it. |
| SEC-23 | Medium | The server advertised an in-memory runtime while authentication and execution still required PostgreSQL. | Fixed: HTTP startup rejects missing/blank database configuration, always uses durable stores, and closes the pool on initialization failure. A startup regression passes. Health remains a liveness/configuration response, not a claim of database readiness or accounting acceptance. |
| SEC-24 | Medium | The demo reused fixed payment IDs with changing fingerprints and placed synthetic funds alongside existing database data. | Fixed: explicit non-production demo mode, random isolated schemas, identical-request replay, reconciliation verification and schema/pool cleanup. Two repeated-run/safety regressions pass. Demo acceptance is not production or bank-provider acceptance. |
| SEC-25 | Medium | CI used deprecated action runtimes and mutable action/image tags. | Updated verified checkout/setup-node release SHAs, removed persisted checkout credentials, pinned Ubuntu 24.04 and added independent Node 22/24 jobs. Both matrix jobs passed for the prior 82-test revision; the final V1 candidate must pass again. Read-only token permissions remain. Official action/release documentation is linked in the project report. |
| SEC-26 | High | Agent credentials or self-declared budgets must not grant unrestricted owner payment authority. | Explicit owner-issued execution scope, exact immutable approvals, live authority/funds checks, shared quotas and atomic held/consumed budgets now govern online agent execution. Existing proposal credentials cannot spend. Replay rechecks authority; rejection/revocation cannot restore spent budget. Local concurrency, rollback and database-invariant regressions pass. Policy holds are not wallet funds. Production deployment/roles/key recovery remain open; no unrestricted autonomous-payment claim is made. |
| SEC-27 | High | Separately committed authorization or an early accepted response could leave partial agent payments or report success before deferred checks fail. | Supplied-client composition now backs the agent executor. Authorization, money, ledger, protected evidence, durable replay, consumed budget, intent linkage and audit share one final commit. Sorted wallet locks skip unrelated expiry sweeps inside the scope. Outer rollback and one-connection concurrency tests pass; a deferred audit failure cannot emit a success receipt. Existing authorization cleanup must run separately. |
| SEC-28 | High | Enabling execution could silently escalate old proposal credentials, accept caller-supplied payment fields or operate with a weak development HMAC secret. | Old scopes are retained; execution requires explicit `payments:execute`, exact fingerprint-only input, server-generated financial fields and a protected composable engine. Missing/short/blank signing secrets block execution and issuance even in development. Reserved agent transaction IDs require an executed-intent binding at commit. Operators must replace weak local signing configuration through a reviewed cutover; secrets were not modified by tests or this implementation. |
| SEC-29 | Medium | Risk observations previously lacked persisted behavioural provenance; client history/device claims or newly rescored retries could misrepresent transaction risk. | Added bounded database-clock history after authority/wallet locking, immutable fingerprint-bound snapshots, explicit cold start/truncation/device limitations and model artifact snapshots. Required observations commit with payments; retries retain them. Participant summaries omit raw features/probabilities. Constant-history rounding regression fixed with Welford statistics. Expanded ML is now optional and shadow-only; trusted fraud labels, risk-record encryption/retention and production evaluation remain open. Shadow reasons never grant authority. |
| SEC-30 | Medium | Supplied ML splits could leak future labels or repeat events across evaluation, while malformed/sparse model vectors and oversized files could produce invalid inference or unbounded work. | Expanded training enforces strict chronological label availability, unique event IDs, feature/provenance schemas, bounded rows/files and finite dense copied vectors. Runtime future cutoffs and currency mismatch produce explicit unavailable observations without fallback. Synthetic labels remain demonstrations; declared confirmed outcomes and source hashes require independent review. Drift, entity leakage, production threshold validation and protected risk-record retention remain open. |
| SEC-31 | Medium | Operational drift checks could mistake tiny cohorts, overlapping events or unavailable labels for evidence of stable model accuracy, or expose individual records. | Added bounded ordered/distinct cohort validation, explicit insufficient-data output, finite smoothed PSI and aggregate-only reporting. CLI exit codes distinguish shift/insufficiency/invalid input and it never updates models or payment policy. Supplied provenance, experimental thresholds, privacy of small aggregates, live monitoring and independent label/calibration verification remain operator gates. |
| SEC-32 | High | Risk features and prediction events retained unencrypted sensitive copies; clear summaries could appear authenticated despite tampering or key loss. | New HTTP records use a separately keyed, purpose/fingerprint-bound AES-GCM/HMAC envelope. Raw feature/hash/prediction copies are NULL, probability events suppressed, and participant summaries require authenticated comparison before exposure. Required-record commit checks, rotation, rollback and offline/agent replay pass. Legacy plaintext stays explicit; retention, historical migration, removed-key inventory, invocation limits and recovery remain gates. Database owners can bypass metadata/triggers; production runtime must be least-privilege. |
| SEC-33 | Medium | Anomaly training could fit holdout data, assign cold-start certainty, divide by zero on constant dimensions, leak detailed distances or interpret unusualness as fraud authority. | Fitted median/MAD parameters, disjoint temporal reference/calibration/test cohorts, finite scale floors/caps and validated copied artifacts now support optional shadow inference. Insufficient/truncated histories remain unscored; SQL summaries exclude raw details and authenticate against encrypted predictions. Replay/migration/rollback pass. Reference contamination/provenance, correlated dimensions, experimental thresholds, real outcomes and hosted latency remain independent gates; anomaly flags grant no payment authority. |

## Verification and release gates

Latest authority increment: 249 local tests pass, zero failures/skips, on 12 October 2026, including live PostgreSQL; the explicit agent suite passes 43. Five new cases cover SQL identity/policy/scope rewrites, revocation reversal and deletion after repeat migration. Expiry tests set deadlines at creation and verify elapsed database time during execution. Existing human, offline, atomic execution and revocation-race tests remain passing. Remote CI/deployment remain unverified for this increment.

- SEC-36 (High): agent identity, credentials and mandates accepted ordinary SQL updates/deletes, allowing a faulty trusted writer to relax previously approved authority or erase history. Fixed with pinned-search-path update/delete guards and permanent revocation. Budget counters remain under deferred consistency guards. This does not prevent DDL, malicious direct inserts by compromised trusted writers or owner-session theft. Runtime roles must not own schema/DDL; agents must have no SQL or owner-key access. Protected authority receipts and independent checkpoints remain planned.

Latest quota increment: 244 local tests pass, zero failures/skips, on 12 October 2026, including live PostgreSQL. Twenty-two new cases cover independent source/identity enforcement, IP/body rotation, pre-authentication protection, malformed requests, event/agent/auth boundaries, concurrent real-database limiter instances, database-clock consistency, invalid parameters, SQL deadlines/failed-client disposal and allowed frontend retry-header visibility. Existing ownership/stream/body-deadline/revocation and financial regressions remain passing. `git diff --check` passes. Explicit CI coverage is configured but not remotely run; no push, chain publication or hosted acceptance occurred. Older counts below are historical.

### Audit and Quota Findings

- SEC-34 (Medium): sparse/unbounded Merkle inputs, partial/duplicated membership and altered proofs could misrepresent coverage. Bounded dense helper validation, atomic pending jobs, authenticated evidence leaves, immutable bound membership and deferred completeness/queue checks are implemented. Crash, migration and participant verification tests pass. SQL does not prove hashes; roots remain local/unanchored and database owners can bypass triggers. Independent checkpoints, finality/reorg, scheduling and coverage acceptance remain open.
- SEC-35 (Medium): composite IP-plus-identity buckets allowed address rotation, while caller-chosen device/wallet buckets bypassed privileged service quotas. Fixed for current routes with independent pre-authentication source and trusted identity quotas; configured issuer quotas ignore body identifiers and key rotation. Malformed requests count. Login retains a hashed-account quota; logout and agent management gain source protection. PostgreSQL samples database time after locking, validates bounded inputs and sets SQL deadlines/discards failed clients. New real-database concurrency/clock-skew tests supplement route regressions. NAT sharing, targeted account throttling, proxy sanitation, edge DDoS controls, quota-row retention and multi-issuer ownership remain operational/future limitations. Namespace changes require consistent writer cutover; no zero-vulnerability claim is made.

Latest audit increment: 222 local tests pass, zero failures/skips, on 12 October 2026. Seventeen cases cover malformed/bounded proofs, protected leaf binding, financial queue rollback, concurrent one-time membership, partial/deferred/real-backend-crash recovery, key retention, envelope/root/proof tampering, SQL completeness/binding checks, participant/IP-rotation access, migration and sanitized finite CLI execution. The initial audit quota test exposed actual IP-plus-identity bypass and was fixed with independent source/identity buckets, not weakened. Remote CI, chain publication and production acceptance remain unverified. Earlier test counts below are historical.

Latest increment: 205 local tests pass on 12 October 2026, zero failures/skips, including PostgreSQL. Thirteen anomaly cases add reference/calibration/test independence, chronology/provenance/bounds, finite constant/extreme inputs, artifact/CLI/benchmark safety, old encrypted-record compatibility, coexistence with logistic inference, encrypted snapshot/replay, unavailable states, SQL summary allowlisting/authentication/rollback and startup checks. The previous 192-test result below is historical. No new dependency was added, and remote CI, deployment or independent real-data acceptance was not run for this increment.

The current local suite passes 192 tests on 12 October 2026, including live PostgreSQL, without skips. Twelve risk-protection cases cover crypto/binding/key separation, rotation/missing keys, immutable required records, raw-copy suppression, summary verification, quotas/rollback and offline/agent retries; the participant API now exercises protected reads. Existing drift, model, financial, intent and composition regressions remain passing. Cleanup is lazy and rolls back on failed operations; no intent expiry worker or automatic history retention is claimed. The earlier `npm audit --json` run reported zero known installed-package advisories on 10 October 2026; it was not rerun for this increment and does not certify application security. CI runs the suite on main pushes and pull requests to main; this revision has not yet run remotely. Expanded ML and offline drift checks are shadow diagnostics, not real-world fraud enforcement or verified live monitoring. Historical reconciliation and production/provider verification remain unpassed release gates.

New HTTP executions now require AES-256-GCM/HMAC protected evidence in the financial transaction. Database binding, immutability and required-evidence checks supplement application verification; they do not perform cryptographic validation inside PostgreSQL. A database owner can bypass triggers and must not be the runtime role. Key versions stay server-side; a missing historical key produces unavailable verification, not a clean audit. The committed-record quota rolls back on failed attempts, so total invocation limits and monitored rotation still require operational controls. Production KMS, independently tested key recovery and historical backfilling are not implemented. Mixed old/new writers and optional V1 library/demo callers are not evidence-complete. Relational fields and existing events are not encrypted by this change.

New HTTP risk records now have a separate required envelope; SEC-29's earlier encryption gap is addressed for those records, not historical plaintext. Risk summaries intentionally remain relational but are verified before API disclosure. No unprotected summary fallback is allowed for marked records. Key-retention/privacy and recovery requirements in SEC-29/30 remain unresolved, and supplied drift cohorts are not automatically exported from protected records. Payment and risk rings must be provisioned before startup; do not commit production keys or interpret passing fixtures as a successful hosted cutover.

Close transaction/recovery, authorization, outbox and ledger findings before real-money integrations. Enable ML decisions only after temporal validation on consented labeled data, calibration, monitored false positives and a deterministic fallback. Anchor audit batches only after commitments are persisted with ledger state and signing ownership, independent checkpoints, finality and chain reorganization handling are implemented.

An audit anchor proves publication of a commitment. It cannot prove authorization, complete inclusion of all payments, or external settlement. Durable local batches and participant proofs are implemented; no blockchain contract, publisher, independent checkpoint or finality tracker is deployed.
